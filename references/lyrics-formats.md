# 歌词格式 · krc / lrc / 纯文本

> 用于：拿到 KTV/音乐客户的歌词文件（酷狗 krc、网易 lrc、纯文本），要变成工程能吃的东西；
> 或反过来——手里只有「无文本的时间表」，要把词填回去。
> 工具：`bin/krc2lrc`（实现在 `scripts/krc2lrc.py`，纯标准库）。

## 一、krc 解密（酷狗）

文件头 `krc1`，之后是加密正文。两步：

1. **16 字节密钥循环异或**：
   `40 47 61 77 5E 32 74 47 51 36 31 2D CE D2 6E 69`（即 `@Gaw^2tGQ61-ÎÒni`），按字节下标 `% 16` 取用。
2. **解出来若是 zlib**（前两字节 `78 9C` / `78 DA`）→ `zlib.decompress`，再按 UTF-8 / GB18030 解码。

- 只有第 1 步、漏掉第 2 步 → 得到一堆二进制乱码，看起来像「密钥不对」。**先看解出来头两字节再判断**。
- 也有不加密的明文 krc：直接是 `[起ms,长ms]<start,dur,flag>字<...>`。两种都要认。

## 二、格式与取词

- krc 行：`[1234,3000]<0,300,0>字<300,300,0>幕` —— `[起,长]` 毫秒，`<start,dur,flag>` 是逐字时间。
- lrc 行：`[mm:ss.xx]文本`，可选 `[ti:] [ar:]` 元信息。
- **要词就剥掉所有 `<...>` 逐字标签**；要时间就取 `[起,长]` 换算。
- 酷狗导出的歌词常**缺念白行**（歌名被单独念一句的那种），转换后行数会比原曲少；别当成转录失败。

## 三、把「无文本时间表」和「自备歌词」拼起来

有的引擎（逐帧 MV 类）只存**无文本的时间表**：每行只有 `start/end/words/letters` 和两个 hash。对接时：

- `x = sha256(整行原文)[:8]`、`h = sha256(行内词小写去标点后以空格连接)[:8]`。
- **对齐按「词数 + 字母数 ± 容差」做，不按字符串相等**：容差一般取 `max(3, 0.3×letters)`，允许行被重新分行（resplit），允许整行跳过（署名/翻译）。
- **缺的那一行可以用 hash 反推**：把候选句（原歌词、念白、歌名各种大小写/标点变体）逐个算 hash 去撞 `x`（严格）或 `h`（宽松）。实测就是这么补回缺失的念白行——比反复调分词快得多。
- 对齐完要看报告：`完全一致 / 重新分行 / 用词不同 / 缺失 / 跳过` 五个数。**「用词不同」只影响按单词触发的镜头，不影响整片播放**；「缺失」才是硬错，必须补。

## 四、命令

```bash
krc2lrc 歌词.krc --out 歌词.lrc     # 带时间
krc2lrc 歌词.krc --txt              # 只要词，一行一句（喂引擎/对齐用）
```

## 五、坑

- 交付目录里同时放 `.lrc` 和 `.txt` 会让「自动找一个歌词文件」的逻辑报歧义——只留一个，或显式指定路径。
- 歌词表时间轴是**歌曲时间**（音频开头 = 0），成片常另加片头 preroll；两者别混。
- 换歌时若开头静音长度不同，整片偏移靠配置里的 `timing.offset` 校正，别去改每一行时间。
