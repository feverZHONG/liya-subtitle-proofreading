# SRT 对照校对流程 ＋ 重建模式 ＋ 错误分类原则

> 2026-09-28 从 SKILL.md 拆出，内容一条未删。

---

## 流程（按序，别跳）


1. **解析 SRT**：按空行分块，每块=序号+时间轴+文本。`re.split(r'\r?\n\r?\n', raw.strip())`（注意 \r\n 或 \n 两种换行）
2. **完整性检查**：块数、序号连续性（1..N 无缺）、时间轴不重叠（后块 start >= 前块 end）。**有问题先报，别急着改字**
3. **规范化全文 diff（核心技巧）**：
   - 字幕与原文不是逐字相同——AI 转写把「1号」读成「一号」、标点全丢、口语化删改
   - 两侧都做归一：去引号/标点/空白 + 阿拉伯数字→中文数字
   - `difflib.SequenceMatcher(None, txt_norm, srt_norm)` 拿 opcodes，统计匹配度 + 列 replace/delete 块
   - 匹配度 >98% 说明对齐良好，剩余差异即错字候选；**别按原文片段直接匹配字幕**——不规范化会大面积「找不到」
4. **定位错词**：diff 里的疑似错词在 SRT 原文 count + 定位到具体块号。⚠️ **跨块**：词被拆到相邻两块时单块 count=0——把相邻两块文本拼接后再查
5. **按块号修正**：维护 `{块号: [(错, 对), ...]}` 替换表，逐块 replace 并打印 before/after 验证；「未找到」的警告单独处理，别静默跳过
6. **验证**：修正后再跑一遍规范化 diff，确认匹配度提升 + 目标错词清零（grep 残留）
7. **交付纪律**：产出「校对版」新文件（`原名-校对版.srt`），**原文件不动**；格式校验通过才交付；git 提交前先让人知道产出在哪

## 重建模式（三轮反馈定版，2026-08-13）


> 第一轮反馈：「字幕的思路是对的，但需要——1. 匹配原稿 txt 内容 2. 别让字幕块过短」。
> 第二轮（贪心合并到平均 23.8 字）被**打回**：「修订反而比之前更难看了」+「字幕过长」+「原文是有章节的，不要断错」。
> **最终形态（v10）**：字幕文本逐字取自原稿 txt + **以原文行为基础分块** + 章节保护 + 块长适中。

- **目标**：规范化匹配度 100%（字幕文本 = 原稿逐字，错字天然消除）；**块长 10-25 字、平均 ~14**（不是越长越好！）；块 = 完整语义单元，不切半句
- 直接跑 `scripts/rebuild_srt.py <srt> <txt> [out] [--max-len 22]`，别手写对齐；块长偏好改 `--max-len`（默认 22），短行合并阈值固定 8
- 流程原理：解析 SRT → 规范化（去标点/数字转中文）→ SequenceMatcher 全局对齐 → **以原文行为基础分块**（短行 <8 合并、长行 >22 按标点拆、无内标点长句 ≤30 保留完整）→ **章节标题（^[1-9]号/^第[一二三]层/^副型[一二三]）强制独立** → 时间轴在原字幕块内插值 → 重新编号
- 合并后必须验证：块数/序号连续/时间轴无重叠/规范化匹配度 100%
- **被批过的错版特征（别重犯）**：贪心合并到平均 20+ 字（过长）；块切在句中间（半句）；标题被并进相邻内容（断错章节）；「而是：」类引导词 3 字单独一闪而过

## 错误分类原则（哪些修哪些不修）


| 类型 | 处理 | 实例（2026-08-13） |
|:--|:--|:--|
| 语义性音误 | ✅ 必修 | 嗜好→四号×6、实时发货→时时发火、生存世界→深层世界、猜步骤→拆步骤、生活基础失去→失序、六号宠物→六号从、慢慢走下→慢慢走向 |
| 章节名/标题转写坏 | ✅ 必修 | 二好→二号、给予行→给予型、李智行→理智型、复型→副型×4、低层层→第一层、依靠→一号 |
| 英文转写崩 | ✅ 按原文还原 | 搜朽→Social、self 减preservation→Self-Preservation、one 减two 减one sexal→One-to-One Sexual |
| 的/地/得 混用 | ⚪ 不修 | 「自然的」vs「自然地」——语音转写通病，不影响理解；**全局替换危险**（「自然的风光」会误伤），只做按块定向修 |
| 他/它 代词 | ⚪ 不修 | 「他会」vs「它会」——口语无差，全改噪音大 |
| 数字写法 | ⚪ 不修 | 百分之百→100%（可接受表达） |
| 符号被转字 | ⚪ 不修 | ≠→非、+→加（语义可通） |
